# Интеграции

## Подход к интеграции

Внешние системы доступны через HTTP-клиенты в сервисном слое. Каждый клиент инкапсулирует протокол взаимодействия, обработку ошибок и логирование. На текущем этапе адаптеры не вынесены в отдельный слой — HTTP-клиент расположен в `app/services/message/`.

Взаимодействие с базой данных изолировано через адаптер в `app/adapters/db/`, который предоставляет async-движок и sessionmaker.

---

## Внешние системы

**PostgreSQL 12** — основное хранилище доменных данных.
Протокол: PostgreSQL через asyncpg и SQLAlchemy async-сессии. Подключение через DSN из переменных окружения. Connection pool с настраиваемым размером (по умолчанию 50) и max overflow (100).

**Message API (campaigner.o3go.ru)** — внешний сервис для получения сообщений и обновления их статусов.
Протокол: HTTP GET через httpx. Аутентификация через заголовок `X-Api-Key`. Клиент расположен в `app/services/message/client.py`, конфигурация URL и таймаута в `MessageSettings`.

**Android-приложения** — потребители внешнего API, работающие на физических устройствах.
Протокол: REST через `/ext/api/v1/`. Аутентификация через API Key. Получают аккаунты, создают сессии, отправляют сообщения, обновляют статусы.

**Внешние системы рассылки** — сторонние потребители внешнего API.
Протокол: REST через `/ext/api/v1/`. Аутентификация через API Key. Используют те же эндпоинты, что и Android-приложения.

**Nginx** — обратный прокси и сервер статических файлов.
Протокол: HTTP. Проксирует запросы к FastAPI-приложению, обслуживает статические файлы из `html/`. Конфигурация в `services/nginx.conf`.

## Расположение интеграционного кода

```
app/adapters/db/              Адаптер базы данных
├── session.py                AsyncEngine + sessionmaker
├── base_class.py             Base модель SQLAlchemy
└── init_db.py                Инициализация БД при старте

app/services/message/         Клиент внешнего Message API
├── client.py                 HTTP-клиент (httpx)
└── schemas.py                Схемы ответов внешнего API

app/deps.py                   Зависимости аутентификации
# get_db — async-сессия БД
# get_current_user — JWT верификация
# get_user_by_api_key — API Key верификация
# get_basic_auth_user — HTTP Basic auth
```

## Надёжность и операционные заметки

- Внешний HTTP-клиент (MessageService) имеет таймаут 30 секунд (настраивается через `MESSAGE_API_TIMEOUT`)
- Сбои внешнего Message API не являются фатальными — клиент логирует ошибку и возвращает None
- Сбой подключения к PostgreSQL является фатальным — приложение не запустится без БД
- Файлы аккаунтов на локальной файловой системе не реплицируются при масштабировании — при нескольких инстансах требуется общий файловый хранилище
- APScheduler работает в одном процессе — при запуске нескольких worker'ов задачи будут выполняться многократно
