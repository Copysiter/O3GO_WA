Загрузить скил `project-context` перед началом.

Выполнить план реализации, последовательно проходя его фазы и отмечая завершение через чекбоксы.

## Использование

```
/task/do [--опции] путь-к-плану
```

## Опции

- `--phase N` — выполнить только указанную фазу вместо полного плана
- `--no-test` — пропустить запуск тестов после фаз (не рекомендуется для продакшн-кода)

## Шаг 1: Загрузка плана

1. Прочитать `plan.md` по указанному пути
2. Убедиться, что frontmatter `status` имеет значение `planned` или `in-progress`
3. Определить все фазы по наличию секций с чекбоксами `- [ ]`
4. Установить текущий прогресс по количеству шагов, уже отмеченных `- [x]`
5. Возобновить выполнение с первого незавершённого шага

Если файл плана не обнаружен, предложить: «План по указанному пути не найден. Создайте его командой `/task/plan`»

## Шаг 2: Контекст проекта

Прочитать следующие файлы из `.opencode/project/` для обеспечения соответствия реализации стандартам проекта:
- `conventions.md` — правила кодирования и соглашения по именованию
- `constraints.md` — технические и архитектурные ограничения
- `architecture.md` — структурные паттерны и границы компонентов

## Шаг 3: Выполнение фаз

Для каждой фазы в последовательном порядке:

1. Прочитать описание фазы и перечень её шагов
2. Выполнить каждый шаг:
   - Создать или модифицировать файлы в соответствии с планом
   - Соблюдать конвенции проекта и архитектурные паттерны
   - Писать тесты параллельно с реализацией, если шаг этого требует
3. Отмечать каждый завершённый шаг как `- [x]` в файле плана непосредственно по завершении
4. После выполнения всех шагов фазы запустить тестовый набор проекта (за исключением режима `--no-test`)
5. При сбое тестов диагностировать и устранить причину до перехода к следующей фазе
6. Запросить у пользователя: «Фаза N выполнена. Перейти к следующей фазе?»

При указании `--phase N` выполнить только эту фазу и остановиться.

## Шаг 4: Обновление статуса

После завершения всех фаз (или указанной фазы):
1. Обновить frontmatter `status`:
   - Все фазы завершены → `status: done`
   - Часть фаз осталась → `status: in-progress`
2. Установить `updated` на текущую дату

## Шаг 5: Отчёт о выполнении

```markdown
## Реализация завершена

**План:** plans/{dirname}/plan.md
**Статус:** done | in-progress
**Фазы:** {выполнено}/{всего}

### Выполнено
- [x] Фаза 1: {название}
- [x] Фаза 2: {название}
- [ ] Фаза 3: {название} (не выполнена)

### Изменения
- Файлов создано: {количество}
- Файлов модифицировано: {количество}

### Тесты
- Результат: pass | fail
- Покрытие: {процент}%

### Следующие шаги
- `/task/review plans/{dirname}/plan.md`
```

## Правила

- Следовать плану точно — не вводить функциональность сверх указанной
- Отмечать чекбоксы в файле плана по мере завершения каждого шага
- Не пропускать шаги без явного разрешения пользователя
- Запускать тесты после каждой фазы, если не активирован режим `--no-test`
- При неоднозначности шага запросить уточнение у пользователя, а не принимать допущения
