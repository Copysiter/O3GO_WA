Загрузить скил `project-context` перед началом.

Внести целевые изменения в конкретный файл проектной документации в `.opencode/project/`.

## Аргументы

`$ARGUMENTS` указывает целевой файл (без пути и расширения) и, опционально, описание требуемого изменения:
overview, architecture, stack, structure, conventions, constraints, integrations

Примеры:
- `ok:project.edit architecture` — открыть architecture.md для редактирования
- `ok:project.edit conventions добавить правило тестирования для API эндпоинтов` — применить конкретное изменение к conventions.md

## Процесс

1. Разобрать `$ARGUMENTS` для определения целевого файла и инлайн-инструкций
2. Если имя файла не распознано, перечислить доступные файлы и уточнить выбор
3. Прочитать текущее содержимое `.opencode/project/{name}.md`
4. Если пользователь предоставил конкретные инструкции в `$ARGUMENTS`, применить их к соответствующим секциям
5. Если инструкции не указаны, уточнить у пользователя, какие изменения необходимы
6. Модифицировать только затронутые секции; сохранить весь остальной контент без изменений
7. Обновить поля frontmatter `status` и `updated`
8. Добавить запись в `.opencode/project/changes.md` с описанием модификации

## Правила

- Не заменять файл целиком; модифицировать только целевые секции
- Не вносить маркеры шаблонов обратно в финализированные документы
- Интегрировать новый контент с существующим материалом, а не перезаписывать
- Поддерживать точный технический язык на протяжении всего документа
- Для существенных правок представить предлагаемые изменения и получить подтверждение перед записью
