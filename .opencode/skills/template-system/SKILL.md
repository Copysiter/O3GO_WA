## Структура шаблонов

Шаблоны представляют собой markdown-файлы, объединяющие YAML frontmatter со структурированными секциями контента.  
Каждый шаблон располагается в `.opencode/templates/` и организован по типу документа:

```
.opencode/templates/
  project/          # шаблоны контекста проекта
  task/             # шаблоны задач и планов фич
```

## Схема frontmatter

Каждый шаблон начинается с YAML frontmatter, определяющего метаданные, правила валидации и текущее состояние обработки:

```yaml
---
template: overview            # идентификатор шаблона
version: 1                    # версия схемы
status: empty                 # empty | partial | complete
updated: "{{date}}"           # дата последнего изменения контента
required_sections:             # должны быть заполнены для status=complete
  - summary
  - purpose
optional_sections:             # могут оставаться пустыми в валидном документе
  - system_context
  - development_notes
---
```

### Жизненный цикл статуса

Документы проходят через три состояния, отражающих степень их завершённости:

- `empty` — шаблон скопирован без изменений, все placeholder'ы сохранены
- `partial` — часть обязательных секций содержит контент, остальные остаются незаполненными
- `complete` — все обязательные секции заполнены содержательным контентом

Обновлять оба поля `status` и `updated` после каждого изменения контента.

## Система маркеров

Шаблоны используют три типа маркеров для управления генерацией контента:

### TEMPLATE_GUIDE

Содержит инструкции по заполнению секции, включая ожидаемый формат, область охвата и уровень детализации:

```markdown
[TEMPLATE_GUIDE]
Что представляет собой проект и что он делает.
Фокус на назначении системы и бизнес-роли.
Формат: 2-4 предложения.
[/TEMPLATE_GUIDE]
```

### TEMPLATE_EXAMPLE

Демонстрирует корректно заполненную секцию, задавая эталон тона, глубины и структуры:

```markdown
[TEMPLATE_EXAMPLE]
Backend API сервис для управления подписками пользователей,
обработки платежей и доставки уведомлений.
[/TEMPLATE_EXAMPLE]
```

### Placeholder'ы

Маркер `{{placeholder_name}}` обозначает точку вставки сгенерированного контента:

```markdown
{{summary}}
```

## Правила обработки

### Инициализация (копирование шаблонов как черновиков)

1. Скопировать файл шаблона без изменений
2. Сохранить все маркеры TEMPLATE_GUIDE, TEMPLATE_EXAMPLE и `{{placeholder}}`
3. Установить frontmatter `status: empty`

### Генерация контента (заполнение шаблонов)

1. Прочитать TEMPLATE_GUIDE — что писать в секции
2. Прочитать TEMPLATE_EXAMPLE — калибровка формата и детализации
3. Следовать подсказкам формата точно («2-4 предложения» → 2-4, не 1 и не 10)
4. Заменить `{{placeholder}}` сгенерированным контентом
5. Удалить блоки TEMPLATE_GUIDE и TEMPLATE_EXAMPLE
6. Обновить frontmatter `status` на `partial` или `complete`
7. Установить `updated` на текущую дату

### Редактирование существующего контента

1. НЕ добавлять обратно маркеры шаблонов
2. Сохранять контент, не затронутый правкой
3. Обновлять только указанные секции
4. Обновить frontmatter `status` и `updated`

## Правила качества контента

- Полные предложения. Каждое утверждение раскрывает суть и обоснование.
- Компоненты по роли, а не по пути к директории
- Списки технологий: название + назначение, только мажорные версии
- Не дублировать между файлами — каждый файл описывает свой аспект
- Только факты, подтверждённые кодом или пользователем. Без спекуляций.
- Неформальный ввод переписывать в точные технические формулировки
- Строго соблюдать ограничения формата из TEMPLATE_GUIDE
- Контент на языке, запрошенном пользователем
- Пути к файлам, команды, ключи конфигурации — на английском

## Валидация

Обработанный документ НЕ должен содержать:
- Блоки `[TEMPLATE_GUIDE]...[/TEMPLATE_GUIDE]`
- Блоки `[TEMPLATE_EXAMPLE]...[/TEMPLATE_EXAMPLE]`
- Маркеры `{{placeholder}}`
- Пустые обязательные секции (из frontmatter `required_sections`)

`status: complete` = все обязательные секции заполнены.
`status: partial` = опциональные секции могут быть пустыми.
