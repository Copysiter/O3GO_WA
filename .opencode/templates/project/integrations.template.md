# Интеграции

## Подход к интеграции

[TEMPLATE_GUIDE]  
Общий подход к интеграции с внешними системами.  
Описать паттерн изоляции и способ внедрения зависимостей.

[TEMPLATE_EXAMPLE]  
Все внешние системы доступны через адаптеры, расположенные в директории адаптеров.  
Каждый адаптер имеет собственную директорию с файлами client, mapper и types, что инкапсулирует транспортные детали и типы данных внутри адаптера.  

Адаптеры реализуют доменные интерфейсы, что позволяет заменить реальную реализацию на мок в тестах без изменения бизнес-логики.  
Внедрение адаптеров в сервисы осуществляется через dependency injection.
[/TEMPLATE_EXAMPLE]

## Внешние системы

[TEMPLATE_GUIDE]  
Каждая важная внешняя или соседняя система.  
Для каждой: название жирным, тире, назначение. На следующей строке — протокол.  
Описать как именно используется в проекте, а не просто название протокола.  
Формат: список записей, каждая 2-4 строки. Единообразная структура.  
[/TEMPLATE_GUIDE]

[TEMPLATE_EXAMPLE]  
**Keycloak** — провайдер идентификации и аутентификации.  
Протокол: OAuth2 / OIDC. Сервис получает JWT-токены от клиентов, верифицирует их локально и извлекает роли из поля resource_access.  

**AccessPoint** — реестр микросервисов платформы.  
Протокол: JSON-RPC. Сервис автоматически регистрируется при старте.  
Регистрация является критической операцией — при сбое сервис логирует ошибку, но продолжает работу.  

**PostgreSQL** — основное хранилище доменных данных.  
Протокол: PostgreSQL через asyncpg и SQLAlchemy async-сессии.  

**Casbin** — система управления политиками доступа.  
Протокол: загрузка файлов конфигурации при старте.  
Энфорсер предоставляется как зависимость через dependency injection.  
[/TEMPLATE_EXAMPLE]

Формат: блок дерева + пояснение. Опционально.

[TEMPLATE_EXAMPLE]
```
app/adapters/
├── jsonrpc/               Адаптер для AccessPoint
│   ├── client.py          Клиент
│   ├── mapper.py          Маппинг данных
│   └── types.py           Типы данных адаптера
└── db/                    Адаптер подключения к БД

app/deps/
├── auth.py                Верификация JWT (интеграция с Keycloak)
├── db.py                  Предоставление async-сессии
└── enforcer.py            Casbin-энфорсер
```

## Надёжность и операционные заметки

[TEMPLATE_GUIDE]  
Требования к надёжности и поведение при сбоях интеграций.  
Для каждого пункта — конкретное правило или факт о поведении системы.  
Формат: маркированный список, 3-6 пунктов. Опционально.  
[/TEMPLATE_GUIDE]

[TEMPLATE_EXAMPLE]
- Все внешние вызовы должны иметь явные таймауты (по умолчанию: 30 секунд)
- Retry с экспоненциальной задержкой применяется для критических операций
- Сбои интеграций логируются со структурированным контекстом: имя адаптера, адрес, код ответа, длительность
- Сбой регистрации в реестре сервисов не является фатальным — сервис продолжает обслуживать запросы
- Health check должен проверять связность со всеми критическими зависимостями
[/TEMPLATE_EXAMPLE]
