## Организация исходного кода

[TEMPLATE_GUIDE]  
Как организован основной исходный код.  
Показать дерево директорий с комментарием к каждой.  
Описать паттерн организации в конце.  
Формат: блок дерева + пояснение, 1-2 предложения.  
[/TEMPLATE_GUIDE]

[TEMPLATE_EXAMPLE]
```
app/
├── api/v1/               Обработчики запросов
│   ├── items.py          CRUD-обработчики сущности Item
│   └── router.py         Регистрация маршрутов
├── services/             Бизнес-логика
│   └── agent.py          Сервис-агент, оркестрирующий операции
├── crud/                 Слой доступа к данным
│   ├── base.py           Абстрактный базовый репозиторий
│   ├── item.py           Репозиторий сущности Item
│   └── filter/           Механизм фильтрации и сортировки
├── models/               ORM-модели SQLAlchemy
├── schemas/              Pydantic-схемы валидации
├── adapters/             Клиенты к внешним системам
│   └── jsonrpc/          JSON-RPC клиент (client, mapper, types)
├── deps/                 FastAPI-зависимости (auth, db, enforcer)
├── middlewares/           Middleware (логирование)
├── core/                 Инфраструктура (config, exceptions, logger)
├── lifespan.py           Управление жизненным циклом
└── main.py               Точка входа, фабрика приложения
```

Каждая доменная область следует предсказуемому паттерну:  
обработчик → сервис → репозиторий → модель.  
[/TEMPLATE_EXAMPLE]

## Конфигурация и окружение

[TEMPLATE_GUIDE]  
Как загружается конфигурация, какие группы настроек существуют.  
Формат: 2-4 предложения + список групп настроек.  
Опционально.  
[/TEMPLATE_GUIDE]

[TEMPLATE_EXAMPLE]
Конфигурация загружается через pydantic-settings из переменных окружения.  
Файл `.env` используется для локальной разработки, `.env.example`  
документирует все обязательные переменные.  

Основные группы настроек:  
- Подключение к БД (`DATABASE_URL`)
- JWT-параметры (ключи верификации, алгоритм)
- Casbin (пути к model.conf и policy.csv)
- Параметры приложения (APP_ENV, APP_PORT)

[/TEMPLATE_EXAMPLE]
