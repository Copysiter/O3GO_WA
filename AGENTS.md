# AGENTS.md

## Агенты

Проект использует пять специализированных агентов, каждый из которых представляет отдельный режим работы. Переключение между агентами осуществляется клавишей **Tab**.

| Агент | Роль | Permissions | Когда активировать |
|-------|------|-------------|-------------------|
| **ask** | Системный анализ, техническая экспертиза, исследование | Только чтение с доступом к MCP | Анализ кода, изучение технологий, вопросы о проекте |
| **architect** | Системная архитектура, планирование, спецификации | Чтение и запись в `.opencode/` и `plans/` | Архитектурные решения, планы реализации, технические спецификации |
| **code** | Реализация | Полный доступ | Написание кода, исправление дефектов, рефакторинг, запуск тестов |
| **debug** | Диагностика | Только чтение с диагностическим доступом к bash | Расследование дефектов, анализ корневых причин |
| **review** | Оценка качества | Только чтение с доступом к git и инструментам верификации | Код-ревью, проверка соответствия, выявление граничных случаев |

Агент по умолчанию: **ask**.

## Рабочий процесс

Стандартная последовательность работы с агентами следует жизненному циклу проекта:

```
ask → architect → code → review
           ↑                |
           └── debug ←───── ↓ (при выявлении проблем)
```

- **ask**: Проанализировать существующий код, изучить технологии, провести исследование
- **architect**: Спроектировать архитектуру, создать план реализации (`/task/plan`)
- **code**: Выполнить план пошагово (`/task/do`)
- **review**: Верифицировать качество и корректность реализации (`/task/review`)
- **debug**: Расследовать сбои и определить корневые причины при возникновении проблем

Для задач с ясным скоупом и минимальной неопределённостью допустимо перейти непосредственно к **code** без предварительного планирования.

## Структура рабочего пространства

```
.opencode/
  agents/       Определения агентов для каждого из пяти режимов работы
  commands/     Слэш-команды, организованные по пространствам имён
    project/    Управление контекстом проекта (/project/*)
    task/       Операции жизненного цикла задач (/task/*)
  skills/       Переиспользуемые модули знаний, загружаемые по запросу
  project/      Документы спецификации проекта (8 файлов)
  templates/    Шаблоны документов для генерации
    project/    Шаблоны проектной документации
    task/       Шаблоны планов задач
plans/          Планы реализации с фазированным выполнением
```

## Приоритет источников истины

При рассуждении о проекте применять следующую иерархию приоритетов:

1. Явные инструкции пользователя
2. Фактическое поведение исходного кода
3. Проектная документация в `.opencode/project/`
4. Артефакты планов в `plans/`
5. Шаблоны в `.opencode/templates/`
6. Правила, определённые в данном файле AGENTS.md
7. Общепринятые инженерные практики

Не допускать предположений о поведении системы, не подкреплённых кодом или документацией.

## Правила безопасности

1. Никогда не выполнять деструктивные операции без явного подтверждения пользователя
2. Никогда не удалять проектную документацию или планы реализации
3. Никогда не модифицировать архитектурные описания без одобрения пользователя
4. Никогда не утверждать поведение системы без подтверждающих доказательств в коде или документации
5. Предлагать масштабные рефакторинги для рассмотрения, а не выполнять их напрямую
6. При столкновении с неоднозначностью запрашивать уточнение, а не принимать допущения

## Формат вывода

- Полные предложения. Каждое утверждение раскрывает суть и обоснование.
- Избегать спекулятивных или желаемых заявлений, описывающих намерения, а не задокументированную реальность
- Преобразовывать неформальные описания пользователя в точные инженерные формулировки
- Поддерживать структурированные секции и единообразное форматирование во всех генерируемых документах
- Явно обозначать нерешённые вопросы в заключении каждого результата

## Языковая политика

Отвечать на **том же языке**, который использует пользователь в своём сообщении.

- Пользователь пишет на русском → отвечать на русском
- Пользователь пишет на английском → отвечать на английском
- Не переводить автоматически без явного запроса пользователя
- Не смешивать языки в рамках одного ответа
- Пути к файлам, CLI-команды и ключи конфигурации сохранять на английском вне зависимости от языка ответа
- Сохранять английский для технических терминов, когда перевод снижает точность формулировки
